# 섹션 5. 아파치 카프카 CLI 활용

> 📅 학습일: 2026-07-26

## 1. 카프카 커맨드 라인 툴

- 카프카에서 제공하는 커맨드 라인 툴(command-line tool)은 카프카 운영 시 가장 많이 접하는 도구
- 토픽/파티션 개수 변경 등 브로커 운영에 필요한 명령을 실행할 수 있음
- 명령 실행 시 **필수 옵션**과 **선택 옵션**이 있음(선택 옵션을 지정하지 않으면 브로커의 기본 설정값 또는 CLI 툴의 기본값으로 대체됨)
- 그러므로 명령 실행 전에 브로커에 옵션이 어떻게 설정되어 있는지 확인하고 사용하면 실수를 줄일 수 있음

---
## 2. 카프카 CLI 실행
- 주키퍼 실행
```text
bin/zookeeper-server-start.sh config/zookeeper.properties 
```

- 카프카 브로커 실행
```text
bin/kafka-server-start.sh config/server.properties 
```

- 카프카 정상 실행 여부 확인
```text
bin/kafka-broker-api-version.sh --bootstrap-server localhost:9092
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

- 테스트 편의를 위한 hosts 설정
```text
sudo vi /etc/hosts

127.0.0.1 my-kafka
```

## 3. kafka-topics.sh

토픽을 생성·조회·수정하는 CLI 툴.

```
--bootstrap-server <host:port>   # 카프카 클러스터 정보 (필수)
--topic <name>                   # 대상 토픽 이름 (필수)
--create                         # 토픽 생성
--partitions <N>                 # 파티션 개수 (선택, 기본값 적용 가능)
--replication-factor <N>         # 복제 개수 (선택)
--config <key>=<value>           # 토픽별 옵션 (예: retention.ms)
--list                           # 토픽 목록 조회
--describe                       # 파티션 수, 복제 개수, 리더/레플리카/ISR 등 상세 조회
--alter --partitions <N>         # 파티션 개수 변경
```

```text
bin/kafka-topics.sh --create --bootstrap-server my-kafka:9092 --partitions 10 --replication-factor 1 --topic hello.kafka2 --config retention.ms=172800000
```

- 클러스터 정보와 토픽 이름만으로도 토픽 생성 가능 (나머지 옵션은 브로커 기본값으로 채워짐)
- **파티션 개수는 늘릴 수만 있고 줄일 수는 없음.** 
- 분산 저장된 데이터를 줄이려면 삭제 대상 파티션 지정 + 기존 레코드 재분산 로직이 필요한데, 카프카는 이 로직을 제공하지 않음. 줄여야 하는 경우엔 토픽을 새로 만드는 편이 좋음

## 4. kafka-configs.sh

토픽/브로커 단위의 세부 옵션을 조회·변경하는 CLI 툴.

```
--alter --add-config <key>=<value> --topic <name>   # 토픽별 옵션 변경 (예: min.insync.replicas=2)
--broker <id> --all --describe                       # 특정 브로커에 설정된 전체 옵션(기본값 포함) 조회
```

## 5. kafka-console-producer.sh

콘솔에서 입력한 메시지를 토픽으로 전송

```
--bootstrap-server <host:port>            # 필수
--topic <name>                            # 필수
--property "parse.key=true"               # 메시지 키를 함께 전송
--property "key.separator=:"              # 키/값 구분자 지정 (미지정 시 기본값은 탭)
```

```text
bin/kafka-console-producer.sh --bootstrap-server my-kafka:9092 --topic hello.kafka
>hello
>kafka
>0
```

```text
bin/kafka-console-producer.sh --bootstrap-server my-kafka:9092 --topic hello.kafka --property "parse.key=true" --property "key.separator=:"
>key1:no1
>key2:no2
>key3:no3
```

- 메시지 키와 값이 함께 전송된 레코드는 토픽의 파티션에 저장됨
- 메시지 키가 **null**이면 프로듀서가 레코드 배치 단위로 **라운드 로빈**으로 파티션에 전송
- 메시지 키가 있으면 키의 해시값을 기준으로 특정 파티션 하나에 고정 배정 → 동일 키는 항상 같은 파티션으로 전송됨

## 6. kafka-console-consumer.sh

토픽에 저장된 데이터를 콘솔로 확인

```
--bootstrap-server <host:port>   # 필수
--topic <name>                   # 필수
--from-beginning                 # 저장된 가장 처음 데이터부터 조회
--property print.key=true        # 메시지 키 함께 출력
--property key.separator="-"     # 키/값 출력 구분자 지정
--max-messages <N>               # 최대 컨슘 메시지 개수 제한
--partition <N>                  # 특정 파티션만 컨슘
--group <name>                   # 컨슈머 그룹 지정
```

```text
bin/kafka-console-consumer.sh --bootstrap-server my-kafka:9092 --topic hello.kafka --from-beginning
```

```text
bin/kafka-console-consumer.sh --bootstrap-server my-kafka:9092 --topic hello.kafka --property print.key=true --property key.separator="-" --from-beginning
```

- `--group` 옵션으로 실행하면 컨슈머 그룹 기반으로 동작. 컨슈머 그룹은 별도 생성 명령이 없고, 컨슈머 실행 시 그룹 이름을 지정하면 자동 생성됨
- 컨슈머 그룹으로 레코드를 가져가면 어느 레코드까지 읽었는지가 카프카 브로커에 저장됨

---

## 7. kafka-consumer-groups.sh

컨슈머 그룹의 조회 및 오프셋 리셋을 담당하는 CLI 툴

```
--list                                  # 생성된 컨슈머 그룹 목록 조회
--group <name> --describe               # 그룹 상태 조회
```

```text
bin/kafka-consumer-group.sh --bootstrap-server my-kafka:9092 --list
bin/kafka-consumer-group.sh --bootstrap-server my-kafka:9092 --group hello-group --describe
```

- `--describe`로 파티션 번호, 현재까지 가져간 오프셋(CURRENT-OFFSET), 파티션 마지막 오프셋(LOG-END-OFFSET), 컨슈머 랙(LAG), 컨슈머 ID, 호스트를 확인할 수 있어 컨슈머 상태 점검에 유용

## 8. kafka-consumer-groups.sh 오프셋 리셋

```
--group <name> --topic <name> --reset-offsets --to-earliest --execute
```

리셋 종류:

| 옵션 | 의미 |
| --- | --- |
| `--to-earliest` | 가장 처음 오프셋(작은 번호)으로 리셋 |
| `--to-latest` | 가장 마지막 오프셋(큰 번호)으로 리셋 |
| `--to-current` | 현 시점 기준 오프셋으로 리셋 |
| `--to-datetime {YYYY-MM-DDTHH:mmSS.sss}` | 특정 일시(레코드 타임스탬프 기준)로 리셋 |
| `--to-offset {long}` | 특정 오프셋으로 리셋 |
| `--shift-by {+/- long}` | 현재 컨슈머 오프셋에서 앞뒤로 옮겨서 리셋 |

## 9. 그 외 커맨드 라인 툴

- **kafka-producer-perf-test.sh**: 프로듀서 성능(처리량·지연시간) 측정용 툴. 
  - `--num-records`(전송 개수), `--throughput`(초당 전송량 제한), `--record-size`(레코드 크기)로 부하 조절
- **kafka-consumer-perf-test.sh**: 컨슈머 성능 측정용 툴. 브로커-컨슈머 간 네트워크 처리량 체크에도 활용
- **kafka-reassign-partitions.sh**: 브로커 간 파티션(리더/팔로워) 배치를 재조정하는 툴. 
  - `auto.leader.rebalance.enable=true`(기본값)면 브로커가 자동으로도 리밸런싱
- **kafka-delete-records.sh**: JSON 파일로 지정한 토픽/파티션의 특정 오프셋 이전 레코드를 삭제하는 툴
- **kafka-dump-log.sh**: 로컬 로그 세그먼트 파일(`.log`)의 실제 내용을 사람이 읽을 수 있게 덤프해서 보여주는 툴 (오프셋, 타임스탬프, 크기 등 레코드 메타데이터 확인용)

---

## 10. 토픽을 생성하는 두가지 방법

- 1) 프로듀서 또는 컨슈머가 존재하지 않는 토픽에 데이터를 요청할 때 자동 생성
- 2) `kafka-topics.sh`로 명시적으로 생성
- 토픽마다 처리되어야 하는 데이터 특성(파티션 개수, 보관 기간 등)이 다르므로, 효과적인 유지보수를 위해서는 **명시적 생성이 권장됨**

---

## 11. 카프카 브로커와 CLI 버전을 맞춰야 하는 이유

- 브로커 버전이 업그레이드되면 커맨드 라인 툴의 세부 옵션도 함께 바뀌기 때문에, 버전 차이가 있으면 명령이 정상적으로 실행되지 않을 수 있음
- 따라서 사용 중인 카프카 브로커와 **동일한 버전의 바이너리 패키지에 포함된 CLI 툴**을 사용해야 함

---

## 정리

- 카프카를 실행하려면 바이너리 파일을 다운로드 받아야 한다
- 카프카 브로커와 커맨드 라인 툴 버전을 맞춰 실행해야 한다
- kafka-topics.sh를 사용하면 토픽을 생성, 수정, 삭제할 수 있음
- kafka-console-producer.sh를 사용하여 토픽에 데이터를 보낼 수 있음
- kafka-console-consumer.sh를 사용하여 토픽의 데이터를 확인할 수 있음
- kafka-consumer-groups.sh를 사용하여 컨슈머 그룹을 조회, 수정할 수 있음
